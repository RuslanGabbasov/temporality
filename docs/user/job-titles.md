# Должности и группы

У каждого сотрудника в профиле есть **должность** — его функция в компании («Инженер тестирования», «Разработчик»). Платформенная роль (admin/operator/viewer) означает права в системе; должность — чем человек занимается. Именно должность — естественный адрес, когда нужно обратиться к функции, а не к человеку по имени.

## Групповые вопросы

Заполните должности в профилях (Users → карточка сотрудника → «Должность») — и агент сможет:

- «Позови всех тестировщиков на созвон» → вопрос получит каждый, у кого в должности «тестировщик»;
- «Отправь разработчикам новую инструкцию» → инструкция уйдёт всем с «разработчик» в должности;
- «Согласуй выкат с кем-то из QA» → вопрос тому, кто первым ответит.

## Как это устроено

Агент адресует вопрос получателем `title:<должность>` — доставка расходится всем подходящим активным сотрудникам (регистронезависимо, по вхождению). Каждый получает свой экземпляр вопроса в своём канале; **первый ответ закрывает вопрос** — остальным уходит пометка, что ответ уже дан. Кто не успел — видит это в истории.

Порядок доставки предсказуем: старше ролью — раньше. Если сотрудник запрещён политикой исполнения, его копия пропускается с пометкой, остальные получают вопрос.

## Поиск людей

Агент находит людей инструментом `human_contacts`: по имени, роли, подразделению и **должности** — карточки показывают, кому и как вопрос дойдёт (адреса каналов не раскрываются, доставка автоматическая).

## Связь с оргструктурой

Должность дополняет подразделения, а не заменяет их: `org:<unit>` адресует команду (всем членам юнита), `title:<должность>` — функцию через весь оргскоп. «Тестировщики» обычно пересекают команды — для этого и нужна должность.

## Заполнение

Users → карточка сотрудника → «Должность». Однострочное поле, свободный формат — главное, чтобы одинаково именовать одну и ту же функцию у разных людей: «Инженер тестирования» и «тестировщик» найдутся одинаково, а вот «QA» и «тестировщик» — разные группы.
