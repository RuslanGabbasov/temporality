# Артефакты

Артефакт — справочный документ в реестре: регламент кодирования, инструкция
по выкладке, шаблон сметы, чек-лист аудита. В промпт агента попадает только
ссылка; тело агент подгружает по требованию (`artifact_search` /
`artifact_read` с аудитом чтения). Так большой регламент не съедает контекст,
но всегда доступен, когда нужен.

Страница **Артефакты** (`/artifacts`), детали — `docs/artifact-registry.md`.

## Типы артефактов

| Тип | Источник тела |
|---|---|
| Текстовый документ | Хранится в Temporality (markdown) |
| Внешний URL | Проксируется и кэшируется ядром (корпоративная вики, Confluence) |

## Согласование

Артефакт может существовать в двух статусах: **черновик** (агент создал —
например, требования из анализа) и **утверждён** (человек отредактировал и
подтвердил). В навыки и промпты ссылаются только утверждённые: так
«смотри регламент X» означает проверенную людьми версию.

Типовой цикл: агент-аналитик готовит документ → отправляет человеку на
согласование (`ask_human` или через артефакт-уведомление) → человек правит
сам или с агентом → утверждает → документ становится доступным всем
агентам-исполнителям как ссылка из навыка.

## Связи

- **Сага** — артефакт может принадлежать длительной работе (требования к фиче в рамках саги).
- **Навык** — манифест навыка ссылается на артефакты как на справочные материалы.
- **Проект / отдел / организация** — область видимости: общекорпоративный регламент виден везде, проектный — только в проекте.

## Инструментальная поддержка

Агенты ищут артефакты по смыслу (`artifact_search`) и читают чанками с
аудитом (`artifact_read`): каждое чтение журналируется — кто, что и в каком
ране читал.
