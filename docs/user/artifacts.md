# Артефакты

Артефакт — справочный документ в реестре: регламент кодирования, инструкция
по выкладке, шаблон сметы, чек-лист аудита. В промпт агента попадает только
ссылка; тело агент подгружает по требованию (`artifact_search` /
`artifact_read` с аудитом чтения). Так большой регламент не съедает контекст,
но всегда доступен, когда нужен.

Страница **Артефакты** (`/artifacts`), детали — `docs/artifact-registry.md`.

## Типы артефактов

| Тип | Источник тела |
|---|---|
| Текстовый документ | Хранится в Temporality (markdown) |
| Внешний URL | Проксируется и кэшируется ядром (корпоративная вики, Confluence) |

## Согласование

Статусы артефакта: **draft** (черновик), **in_review** (отправлен на ревью),
**rejected** (отклонён с вердиктом) и **approved** (утверждён). В навыки и
промпты ссылаются только утверждённые: так «смотри регламент X» означает
проверенную людьми версию.

Ревью-цикл: автор отправляет артефакт на ревью (идемпотентно по версии,
квота `ARTIFACT_SUBMIT_PER_DAY` на ран) → ревьюеры получают уведомление →
решение принимает **только человек** (само-одобрение запрещено на уровне
API). Ревьюеры настраиваются с режимом `all` (должны решить все) или `any`
(достаточно одного). Отклонение возвращает артефакт автору с причиной.

Решить можно в интерфейсе (страница «Артефакты») или прямо в мессенджере:
ответом на уведомление — первое слово решает (`approve`/`одобрить` — за,
`reject`/`отклонить` — против, остальное — комментарий). Если круг висит без
решения дольше `ARTIFACT_REVIEW_TIMEOUT` (по умолчанию 72 часа), ревьюеры
получат одно напоминание, а ещё через столько же — эскалация руководителю
отдела артефакта (или администратору). Типовой цикл: агент-аналитик готовит
документ → отправляет на ревью → человек правит сам или с агентом →
утверждает → документ становится доступным всем агентам-исполнителям как
ссылка из навыка.

## Связи

- **Сага** — артефакт может принадлежать длительной работе (требования к фиче в рамках саги).
- **Навык** — манифест навыка ссылается на артефакты как на справочные материалы.
- **Проект / отдел / организация** — область видимости: общекорпоративный регламент виден везде, проектный — только в проекте.

## Инструментальная поддержка

Агенты ищут артефакты по смыслу (`artifact_search`) и читают чанками с
аудитом (`artifact_read`): каждое чтение журналируется — кто, что и в каком
ране читал.
