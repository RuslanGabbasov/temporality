# Быстрый старт

## Требования

- Docker с Compose v2.23.3+ (Linux, macOS; Windows — через WSL2). Рекомендуется BuildKit.
- ~4 ГБ свободной памяти для стека (PostgreSQL, Temporal, Journal, Kernel, UI).
- Ключ любого OpenAI-совместимого провайдера (OpenAI, OpenRouter, локальный
  Ollama и т.д.) — понадобится в мастере онбординга на третьем шаге.

Больше ничего: модель, первый агент, песочница и модель-супервайзер
настраиваются в мастере при первом запуске — `.env` для этого не нужен.

## Запуск

Готовые образы из GHCR — рекомендуемый путь, ничего клонировать и собирать
не нужно.

Установка одной строкой (рекомендуется новичкам): скрипт проверит окружение,
скачает compose-файл, поднимет стек и дождётся готовности:

```sh
curl -fsSL https://raw.githubusercontent.com/RuslanGabbasov/temporality/main/install.sh | sh
```

На сервере, где Docker требует root, направьте пайп в sudo:
`curl -fsSL … install.sh | sudo sh` — sudo перед curl не помогает, скрипт
запустится без прав. Или добавьте себя в группу docker:
`sudo usermod -aG docker $USER` (затем перелогиньтесь).

Вручную, без скрипта — compose-файл самодостаточен (динамический конфиг
Temporal и настройки SearXNG встроены в него через `configs:`), а флаг
`--wait` держит команду до готовности стека:

```sh
mkdir temporality && cd temporality
curl -O https://raw.githubusercontent.com/RuslanGabbasov/temporality/main/docker-compose.yml
docker compose up -d --wait
```

Если какие-то из портов 3000 (UI), 8080 (journal), 8090 (kernel), 8233
(Temporal UI) или 5432 (postgres) заняты на сервере — установщик проверит
их до старта и подскажет; переопределить можно в `.env` рядом с
compose-файлом, например `UI_PORT=3001`.

По умолчанию поднимается последний опубликованный релиз (образы — из
[релизов](https://github.com/RuslanGabbasov/temporality/releases)). Для
контролируемого обновления версию можно закрепить:
`TEMPORALITY_VERSION=2026.2.113 docker compose up -d --wait`. Обновление до
новой версии: `docker compose pull && docker compose up -d --wait` (или
`… install.sh | sh -s -- update`) — миграции применяются ядром на старте.

Скрипт-установщик умеет ещё два режима: `… install.sh | sh -s -- doctor` —
диагностика установки (docker, версия compose, состояние контейнеров,
доступность портов), `… install.sh | sh -s -- uninstall` — остановить и
удалить стек (данные в томах остаются; `--purge` удалит и их).

### Без установки: GitHub Codespaces

Попробовать полный стек можно прямо в браузере, без локального Docker:
кнопка открывает кодспейс, поднимает весь compose-стек (включая песочницу —
в кодспейсе работает Docker-in-Docker) и открывает интерфейс:

[Открыть в GitHub Codespaces](https://codespaces.new/RuslanGabbasov/temporality)

Что важно знать:

- личному аккаунту GitHub даётся 120 core-часов Codespaces в месяц бесплатно
  (машинка по умолчанию — 2 ядра / 8 ГБ, стек помещается); это квота вашего
  аккаунта, проект ничего не платит;
- первый запуск тянет ~2 ГБ образов во внутренний Docker — несколько минут;
- кодспейс засыпает после ~30 минут простоя: данные сохраняются, пробуждение
  занимает около минуты. Полная пересборка контейнера сбрасывает всё, кроме
  `/workspaces` (песочница специально живёт там);
- это путь «попробовать», не продакшен: квоты и время жизни кодспейса
  ограничены.

Сборка из исходников (для разработки самого Temporality):

```sh
git clone https://github.com/RuslanGabbasov/temporality.git && cd temporality
docker compose -f docker-compose.yml -f docker-compose.dev.yml up --build -d
```

Поднимаются: PostgreSQL, Journal (`:8080`), UI (`:3000`), Temporal (UI `:8233`),
Agent Kernel (`:8090`), SearXNG (`127.0.0.1:8889`, метапоиск для агента) и
headless-браузер Lightpanda.

Остановить стек, сохранив данные: `make stack-stop`.

## Онбординг

Откройте `http://localhost:3000` — мастер проведёт через настройку и спрячет
навигацию, пока она не пройдена:

1. **Первый проект** — рабочая область для задач агента.
2. **Администратор** — ваш пользователь (после шага анонимный доступ закроется).
3. **Провайдер моделей** — base URL и ключ: кнопка проверит ключ и подтянет
   каталог моделей автоматически. Провайдер и ключ хранятся в базе; ключ
   шифруется — если `KERNEL_SECRET_MASTER_KEY` не задан, ключ шифрования
   генерируется при первом старте и сохраняется рядом. Для продакшена задайте
   эту переменную в env до первого запуска, чтобы секреты пережили перенос
   базы.
4. **Песочница** — выберите готовый профиль окружения (Node, Python, Browser
   E2E) и соберите его образ в один клик (нужен доступ к Docker daemon).
   Можно пропустить и собрать позже.
5. **Первый агент** — из шаблона: контракт, права и роль уже настроены
   (Coder, Reviewer, Researcher, QA, DevOps). Останется назвать и выбрать
   модель.
6. **Модель-супервайзер** — модель, которая наблюдает за запусками и судит
   эволюцию агентов. По умолчанию — та же, что у агента; меняется потом в
   настройках.

Два случая, когда мастер ведёт себя иначе:

- задан `KERNEL_AUTH_TOKENS` — аутентификация включена вашим же env: мастер
  не стартует анонимно, войдите одним из этих токенов (режим «API-токен»)
  или закомментируйте переменную для анонимного онбординга;
- задан `KERNEL_SANDBOX_IMAGE` — образ песочницы закреплён вашим env: шаг
  сборки предлагается пропустить.

Модель провайдера можно добавить и через env
(`TEMPORALITY_MODEL_BASE_URL` / `_ID` / `_API_KEY`) — это legacy-fallback
«модели по умолчанию» для ранов без явной модели; мастер онбординга —
основной путь.

## Первая задача

Откройте **Workspace** — чат с агентом — и напишите задачу. Агент ответит
стримингом; по ходу работы он может:

- выполнить команды в песочнице (`/workspace` проекта — персистентное хранилище),
- делегировать подзадачи другим агентам (`plan`/`delegate`),
- задать вам вопрос через **подтверждение** (карточка в чате, дублируется в «Запусках»),
- записать полезное наблюдение в знания проекта.

После завершения загляните в **Запуски** (трасса шаг за шагом) и **Знания**
(что агент вынес из задачи).
