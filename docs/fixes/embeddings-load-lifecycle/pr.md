## Проблема

На локальной установке readiness-чек `embeddings` бесконечно показывает `detail: "load not attempted"` (а `fix` — статичную подсказку «Wait for the model to load…»), хотя попытка загрузки embedding-модели (`intfloat/multilingual-e5-small` через `rembed`) падает. Причина сбоя оператору недоступна: оркестрация загрузки в ядре теряла текст ошибки. Замеры установки: сеть из контейнера до huggingface.co/CDN работает (~2.3 МБ/с), кэш `REMBED_CACHE` пуст и записываем, переменные окружения корректны.

## Дефекты (устранены)

- **D1** — при ошибке `rembed.Load` канал `ready` не закрывался (закрывался только при успехе): ожидающие в `getEmbedder` висели до таймаута и получали ложную ошибку «embedding model is still loading — retry shortly».
- **D2** — `EmbeddingsStatus` показывал «load not attempted» даже после упавшей попытки; текст ошибки не выводился ни в статус, ни в readiness `detail`.
- **D3** — латентный дедлок: ветка ошибки `getEmbedder` брала `embedMu.Lock()` второй раз на уже удерживаемом нерекурсивном мьютексе.
- **D4** — авто-повтора не было: повтор инициировали только вызовы `EmbedTexts`, а бэкфилл звал их лишь при наличии знаний без векторов → пустая база означала «load not attempted» навсегда.
- **D5** — исход загрузки (успех/ошибка, модель, кэш, длительность) не логировался вообще.

## Что сделано

- `kernel/agent/embeddings.go` — машина состояний перестроена вокруг `embedAttempt{ready, embedder, err}`: каждая попытка владеет каналом, закрываемым **и при успехе, и при ошибке**; ожидающие получают реальную ошибку немедленно; ровно одна загрузка в полёте; двойной лок устранён. `EmbeddingsStatus.Error` несёт реальную причину (`lastErr`), «load not attempted» — только до первой попытки.
- Авто-повтор с экспоненциальным бэкоффом `30s → 5min` (`time.AfterFunc`, генерационный `retrySeq` защищает от stale-таймеров) — **независимо** от наличия знаний без векторов; внешний вызов может запустить немедленный повтор.
- Логирование: каждая неудача — `slog.Error` (модель, кэш-каталог, ошибка, длительность, попытка, `retry_in`); успех — `slog.Info` (модель, длительность).
- Инъекция загрузчика `var loadEmbedder = rembed.Load` + 8 юнит-тестов: успех; ошибка (статус с реальной причиной, канал закрыт, ожидающие не зависают); авто-повтор; отсутствие дедлока; одна загрузка в полёте.
- `cmd/agent-kernel/main.go` — строка `fix` readiness-чека уточнена под новый жизненный цикл.

## Контракты сохранены (R6)

JSON `EmbeddingsStatus` (`model`/`ready`/`error`) и ключи readiness-чека (`key`/`configured`/`used_by`/`fix`/`detail`) не менялись по структуре; поменялась только семантика `error`/`detail` — теперь они несут реальную причину.
