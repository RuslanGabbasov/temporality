## Краткий ответ пользователю

Ядро НЕ «жёстко падало» единым событием. Произошло наложение трёх вещей:
1. Три активных прогона зависли внутри вызова модели (последнее событие каждого — `model.started`,
   14:09:15 / 14:13:38 / 14:28:55), и по ним не сработала даже штатная лестница ретраев —
   раны навсегда остались «started».
2. Отправка сообщений в чат упиралась в `POST /v1/workspace/tasks/{id}/runs`: сама задача
   создавалась (4 строки `sozday-pr-*` в БД), но старт рана не проходил — браузер получал
   транспортный `NetworkError` без HTTP-ответа. Параллельно процесс ядра перезапускался
   несколько раз (буты 10:52, 10:53, 14:15, 14:29, 14:59 по событиям `storage.snapshot`).
3. «Пропавший список проектов» — дефект UI: `loadProjects` при ошибке молча показывал пустой
   список; вы перезагружали страницу (доказано 4 дублями одной задачи: `taskId` в транскрипт
   чата не сохраняется), и при недоступности API селектор пустел.

Провайдер модели сегодня нестабилен (`PROTOCOL_ERROR`, `unexpected EOF`, стрим-таймауты) —
это внешний триггер зависших вызовов. Восстановление только через down/up — согласуется с
состоянием, которое не лечится само.
