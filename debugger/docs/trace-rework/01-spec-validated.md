## 2. Результат валидации требований (полнота / непротиворечивость / реализуемость)

**Полнота.** Документы самодостаточны для реализации клиентской части. Выявлены 2 пробела, закрытые решениями ниже:
- **V-1 (пробел, закрыт):** буфер хвоста и поведение при переполнении не зафиксированы. **Решение:** 256 КБ **или** 2000 строк (что раньше), при переполнении отбрасываются старые записи с явным маркером усечения в UI.
- **V-2 (пробел, закрыт):** бюджет запросов «открытие вкладки» включает ли список открытых human-запросов. **Решение:** в бюджет ≤3 запросов (NFR-1) входят: batch-список ранов, открытые human-запросы, опционально ops-запрос; всё остальное — лениво.

**Непротиворечивость.** После применения дельт противоречий не остаётся: все расхождения §7/§11 базового дока с v0.3 разрешены в пользу v0.3 (таблица §1). DoD-2 сужен до: сырой JSON аргументов недоступен из таймлайна + `secret.*`-redaction; allowlist-проекции не требуются.

**Техническая реализуемость (с ограничениями — включены в объём работ):**
- **V-3 (ограничение, подтверждено кодом):** сервер сейчас буферизует вывод `run_command` до завершения команды (`kernel/sandbox/docker.go:340–357`, `result.Output` собирается после `cmd.Run()`). Настоящий live-стрим (п. D) невозможен без серверной правки. **Решение:** в объём T3 входит серверная поддержка: кольцевой буфер in-memory на `operation_id` (без персистентности), эндпоинт тейла (SSE либо опрос — требование допускает «SSE/интервал»), поток адресуется `console://<operation_id>`. Прецедент в коде: ephemeral token stream (`cmd/agent-kernel/main.go:3224`). Если серверная часть не укладывается — фиксируется как «сделано, но не проверено» с явным указанием, а клиентский контракт (ленивость, буфер, вкладки stdout/stderr, copy, AbortController, `document.hidden`) реализуется полностью.
- **V-4 (ограничение, подтверждено кодом):** NFR-1 требует batch-эндпоинт списка ранов — сейчас список строится 4 сканами журнала (`AgentRuns.tsx:519–526`) + N+1 (`:549–551`). Серверный `GET /v1/agent/runs` (курсорная пагинация, статус в строке) добавляется в `cmd/agent-kernel/main.go` — реализуемо.
- **V-5 (интерпретация, зафиксирована):** NFR-2 «выбор рана — 1 запрос таймлайна»: на выбор — ровно 1 запрос страницы событий (50–100, курсор); result/costs/trajectory/вывод — лениво (открытие вкладки / раскрытие). Существующий догон курсоров `runEvents(run)` (`AgentRuns.tsx:596–604`) сохранить (требование NFR-4).
- **V-6 (зафиксировано):** `model.text_delta`/`model.reasoning` не создают строк таймлайна, питают live-строку вызова модели; при раскрытии — полный текст.
- **V-7 (зафиксировано):** K-1: human-форма аргументов в слое 2, сырой JSON — только слой 3 (для аргументов allowlist не требуется; инвариант — только `secret.*`).

## 3. Итоговый объём (требования к реализации)

**A. Трёхслойная модель.** Слой 1 «Таймлайн» (одна строка на событие: иконка/цвет по смысловой категории, заголовок ≤120 символов, ключевой факт, длительность, статус). Слой 2 «Детализация» — инлайн-раскрытие «что произошло и что делать» (аргументы human-формой, результат, причина ошибки через `explainKernelError`, ссылки дочерний ран/знание/консоль, прогресс/вывод для долгих операций). Слой 3 «Сырое событие (JSON)» — свёрнутая секция в конце детализации. Кнопка «Детализация» удалена. Название типа события в UI не показывается (кроме слоя 3).

**B. Декларативный каталог представления.** Замена switch `eventSummary.ts:197–628` таблицей `type → {timeline, details, raw}` с источником истины `eventCatalog.ts`; generic-шаблон для незнакомых типов (не сырой JSON). Покрытие 100% типов каталога + псевдо-инструменты (`run_command`, `skill_*`, `mcp__*`, `browser`, `send_file`, …) + streaming-типы. Сводки по группам (runs вкл. `run.note_dropped` с CTA «повторить»; model: ретраи `attempt/nudged` жёлтым; tools: файловые — диф-превью, `tool.failed/blocked` — причина + CTA; delegation/plans — дерево лениво, транзиции плана свёрнуты, комментарий ревьюера при `rejected` видим; approvals/human — 1 строка на пару запрос/решение, карточка-CTA; knowledge/hints — агрегаты «3 подсказки, 2 использованы»; artifacts — имя/версия/ссылка `artifact://`; secrets — только имя/статус/причина; mcp/triggers/intake — конвейер одной строкой; skill/agent.definition/agent.evaluation — блок «Эволюция агента», гейт-блокировки красным; saga — свёрнуто; ops-шум (`storage.snapshot`, `operation.reconciled`, `notification.sent`, `memory.read.failed`) — свёрнут/фильтруем).

**C. Приватность.** Никакой redaction/allowlist-проекции на стрим stdout/stderr. ЕДИНСТВЕННЫЙ инвариант: значения `secret.*` не отображаются ни на одном слое (только имя/статус/причина; `secret.value_set` → «значение задано»). knowledge/137 — отложенная задача аудита, не блокер.

**D. Стрим вывода `run_command` (`console://<operation_id>`).** Без персистентности: live-стрим + буфер хвоста 256 КБ / 2000 строк (переполнение — отброс старых + маркер). Лениво: только при раскрытии события выбранного рана. Live-тейл (SSE/интервал) пока команда работает, стоп по `tool.completed/failed`; отмена через `AbortController`; пауза при `document.hidden`. Первые 64–256 КБ + авто-перемотка к хвосту (с ручной паузой), «Показать полностью» — дозапрос диапазона. Разделение stdout/stderr (вкладки/префикс), подсветка ошибок, кнопка «копировать». В UI нет `artifact://`-ссылок на консольный вывод. Ограничение (без хранения): серверный поиск по выводу невозможен — явно фиксируется в UI/доке.

**E. Рефакторинг загрузки.** NFR-1: открытие ≤3 запросов; batch-список ранов (курсор, страница 50–100); устранить N+1 `AgentRuns.tsx:549–551` и 4 скана `:519–526`. NFR-2: выбор рана — 1 запрос таймлайна (страница 50–100, курсор), остальное лениво. NFR-3: дети — мета-строка делегирования + ленивая догрузка (не `Promise.all`, `AgentRuns.tsx:606–622`). NFR-4: `AbortController`, кэш/дедупликация по `run_id`, без новых сканов журнала (существующий догон `:604` — сохранить). NFR-5: виртуализация таймлайна (окно 50–100 строк), ≤2000 DOM-узлов трассы, тяжёлые тексты лениво. NFR-6: polling только выбранного рана (`:655`), интервал ≥5 с (сейчас 10 с — ок), `document.hidden` → пауза; SSE-тейл только выбранного рана. NFR-7: до содержательного рендера ≤1.5 с при 100 ранах / 20 Мбит/с; бюджеты запросов закрепить perf-guard тестами. NFR-8: все новые строки — через `locales/ru.ts` + `locales/en.ts`, существующие тесты локалей зелёные.

**F. Фильтры и поиск.** По категории/типу/статусу/участнику/длительности; быстрые чипы («Только ошибки», «Только инструменты», «Только решения человека», «Только мой ввод»); текстовый поиск (заголовки/детали/human-форма; поиск по выводу — в пределах загруженного окна и буфера). Дебаунс ≥300 мс; без сетевых запросов на символ. Состояние фильтров/поиска — в URL (query params). Ограничение поиска по выводу — явно в UI.

**G. Дефекты базового состояния.** K-1 `AgentRuns.tsx:1021` `json(operation?.arguments ?? details)` → human-форма в слой 2, сырой JSON в слой 3. K-2 `:549–551` N+1 → NFR-1. K-3 `:523–526` `.catch(() => ({events: []}))` → `partial: true` + индикатор «статусы недоступны» + логирование. K-4 `eventSummary.ts:197–628` switch → декларативная таблица. Нелокализованный `by ${approver}` (`eventSummary.ts:409`) → i18n.

## 4. Критерии готовности (DoD) — на каждый пункт требуется подтверждение в отчёте

1. Таблица «тип → таймлайн → детализация → сырой» покрывает 100% типов; непокрытые — generic-шаблон, не сырой JSON.
2. Значения `secret.*` не отображаются ни на одном слое (автотест redaction); сырой JSON недоступен из таймлайна.
3. Число сетевых запросов на открытие вкладки (≤3) и на выбор рана (=1) закреплено тестами (perf-guard).
4. Нет регрессии: `eventSummary.test.ts`, `eventCatalog.test.ts`, `teamRuns.test.ts`, `locales.test.ts` и др. — зелёные (минимальные правки тестов допустимы только при осознанной смене внутреннего API — фиксировать в отчёте с обоснованием).
5. Статический анализ без новых замечаний (`npm run build` = `tsc -b && vite build`; ESLint в проекте не настроен — зафиксировать это в отчёте); локальность изменений; новые unit-тесты: форматирование представления, стриминг вывода (`console://`), secret-redaction, perf-guard.
6. Доступность: раскрытие детализации с клавиатуры, aria-метки.
7. DoD-базы: фильтры/поиск с тестами и состоянием в URL; live-стрим + буфер хвоста через `console://`, в UI нет `artifact://` на вывод; кнопка «Детализация» удалена.

## 5. Жёсткие ограничения

- Не изменять семантику событий журнала (имена типов, поля, смысл).
- Сохранить существующий polling выбранного рана и SSE-тейл (`journalStream.ts`).
- Все новые пользовательские строки — через слои i18n (ru + en).
- `console://` — единственный адресат консольного вывода; `artifact://` — только для артефактов.
- Значения `secret.*` — никогда, ни на одном слое.
- Приоритет при нехватке ресурса: E (загрузка, K-2/K-3) → B+G (каталог, K-1/K-4, удаление кнопки) → D (console://) → F (фильтры) → A (визуальная полировка). Цель — всё целиком; незавершённое фиксировать честно.
