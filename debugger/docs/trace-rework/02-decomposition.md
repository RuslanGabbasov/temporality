## Правила взаимодействия

- Каждый этап получает самодостаточный промпт (цель, контекст, входные данные, критерии готовности, формат отчёта) — см. `03-developer-prompts.md`.
- Отчёт каждого этапа сохраняется в `debugger/docs/trace-rework/reports/tN-report.md` (дифф `Файл:Строка`, точные команды тестов/стат. анализа с полным выводом, таблица статусов).
- Незавершённое фиксируется честно в отчёте (категории: «сделано и проверено» / «сделано, но не проверено» / «не сделано»); приоритет при переполнении: E → B+G → D → F → A.
- Запрещено: менять семантику событий, удалять polling выбранного рана, показывать значения `secret.*`, использовать `artifact://` для консольного вывода.

## Риски

| Риск | Митигация |
|---|---|
| Серверная часть D (live-вывод) объёмнее клиентской | V-3: при незавершении серверной части — клиентский контракт полный, статус «сделано, но не проверено» с описанием разрыва |
| Тесты на внутренний API (`eventSummary`) меняются при K-4 | DoD-4: минимальные правки тестов только при смене внутреннего API, обоснование в отчёте |
| Переполнение бюджета этапа | Честная фиксация незавершённого + дорабатывающие итерации по вердикту R1 |

## Пересборка DAG (итерация 2, по указанию оператора)

**Инцидент:** plan-движок задеплоил задачи t2–t4 параллельно с выполнявшейся t1 (доказательства: t2-report.md и r1-review.md — 11:35, тогда как файлы T1 `cmd/agent-kernel/runlist_test.go` — 12:08, `debugger/src/runsLoad.ts` — 12:23). t2/t3/t4 увидели дерево без правок T1, запросили указания у оператора. Оператор: «пересобрать правильно задачи в DAG».

**Исправленный DAG и способ исполнения:**
```
T1' (доводка T1: загрузка) → T2' (каталог, слои, K-1/K-4) → T3' (console://) → T4' (фильтры/URL/полировка + сводный отчёт) → R1' (quality-гейт)
```
