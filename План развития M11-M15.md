# M11 — World Interface: базовые возможности взаимодействия с внешним миром

Цель M11 — дать агенту минимальный, но настоящий набор физических возможностей, не ломая FRP abstraction.

### 11.1. World Capability Model

Добавить отдельный тип capability:

```
WorldCapability
```

с категориями:

```
observe
read
write
execute
communicate
navigate
```

Например:

```
filesystem.read
filesystem.write

process.execute

http.read
http.write

git.read
git.write

browser.navigate
browser.read
browser.interact

mcp.call
```

Важно: capability ≠ affordance.

```
Capability
    ↓
что физически разрешено

Affordance
    ↓
какое осмысленное действие доступно агенту
```

Например:

```
run_reproduction_test
```

может требовать:

```
process.execute
filesystem.read
filesystem.write
browser.navigate
browser.read
```

---

### 11.2. World Resource Model

Появляется описание доступного окружения:

```
World
 ├── resources
 ├── capabilities
 ├── identities
 ├── credentials
 ├── limits
 └── policies
```

Например:

```json
{
  "world_id": "workspace-42",
  "resources": [
    {
      "id": "repo",
      "type": "git_repository",
      "path": "/workspace/repo"
    },
    {
      "id": "browser",
      "type": "browser",
      "endpoint": "..."
    }
  ],
  "capabilities": [
    "filesystem.read",
    "process.execute",
    "git.read",
    "browser.navigate"
  ]
}
```

World должен иметь версию/идентификатор состояния, чтобы replay понимал, **в каком окружении происходило действие**.

---

### 11.3. Read-only World Affordances

Сначала реализовать только наблюдение:

```
inspect_workspace
list_files
read_file
git_status
git_diff
git_log
inspect_environment
inspect_processes
inspect_http
inspect_browser_page
```

Все результаты проходят через существующий Execution/Event pipeline.

Например:

```
Agent
 ↓
inspect_workspace
 ↓
Affordance Resolver
 ↓
Executor
 ↓
filesystem adapter
 ↓
execution.result
 ↓
Event
 ↓
Claim / Projection
 ↓
Render
 ↓
Agent
```

То есть **не вводить отдельный механизм "context injection"**.

Внешний мир становится частью Memory только через события.

# M12 — Write/Action World

После того как агент умеет смотреть, дать ему возможность менять внешний мир.

### 12.1. Filesystem

```
create_file
write_file
patch_file
delete_file
move_file
```

### 12.2. Process

```
run_command
start_process
stop_process
```

### 12.3. Git

```
create_branch
checkout
commit
apply_patch
```

### 12.4. HTTP

```
http_get
http_post
```

Но эти primitive операции **не должны попадать непосредственно в CognitiveEmission как основной интерфейс**.

Агент по возможности работает с semantic affordances:

```
fix_bug
run_tests
inspect_repository
reproduce_issue
update_configurationа primitives остаются строительными блоками Executor.
```

---

### 12.5. Effect Boundary

Для каждой операции должна существовать явная граница:

```
proposal
    ↓
policy validation
    ↓
persist intent
    ↓
effect
    ↓
persist resultто позволит после M12 ответить на фундаментальный вопрос:
```

> Что именно произошло во внешнем мире и почему Runtime считает, что это произошло?

# M13 — Bootstrap Knowledge

Сейчас substrate пустой:

```
Events = почти 0
Claims = 0
Regions = 0
Procedures = 0
```

Поэтому Attention Engine технически работает правильно — ему просто нечего находить.

Нужен механизм первоначального заселения substrate.

---

## 13.1. Knowledge Import Pipeline

Вводится:

```
Source
  ↓
Ingestion
  ↓
Observation Events
  ↓
Claims
  ↓
Entities / Regions
  ↓
Edges
  ↓
Embeddings
  ↓
Procedures
```

Источниками могут быть:

```
filesystem
Git repository
documentation
URLs
HTTP APIs
MCP resources
database
uploaded files
existing agent memory
```

---

## 13.2. Import не должен напрямую создавать Claims

Это важный инвариант.

Например, файл содержит:

```
"Platform uses React Router."
```

Нельзя сразу сделать:

```
Claim:React Router is used by Directum RXconfidence = 1
```

Нужно сохранить provenance:

```
Observation
    ↓
source
    ↓
extraction
    ↓
ClaimНапример:
```

```
E100:
source=documentation.md
location=L42
content="..."

C100:
proposition="..."
confidence=0.82
evidence=[E100]
```

Это позволит отличать:

```
что было найдено
```

от:

```
что substrate считает истинным.
```

# M14 — Entity / Knowledge Graph Bootstrap

Здесь я бы расширил текущую Region model.

Сейчас:

```
Event → Claim → Region
```

достаточно для когнитивного PoC, но для реального агента нужен более явный слой сущностей.

Не обязательно вводить Neo4j.

В PostgreSQL:

```
Entity
EntityType
EntityAlias
EntityMembership
EntityRelationНапример:
```

```
Superapp
   │
   ├── uses → React
   ├── uses → Synapse
   ├── contains → Matrix
   ├── integrates → Platform
   └── repository → webА Claims становятся утверждениями о сущностях:
```

```
Claim
 ├── subject
 ├── predicate
 ├── object
 ├── confidence
 ├── evidence
 └── temporal validityТо есть постепенно получаем:
```

```
                    ┌──────────────┐
                    │    Entity    │
                    └──────┬───────┘
                           │
                     has relation
                           │
                           ▼
Claim ────────────────→ Entity
 │
 └── evidence → Event
```

Это намного полезнее для Attention, чем просто набор абстрактных Regions.

# M15 — Agent Bootstrap / First Contact

После M11–M14 появляется интересный новый сценарий.

Агент получает задачу:

> Разберись, почему тест падает.

Но substrate первоначально пуст.

Вместо того чтобы сразу начинать hallucinate, Runtime создаёт:

```
Bootstrap Episode
```

и запускает ограниченный цикл discovery:

```
Objective
   ↓
World inspection
   ↓
Repository discovery
   ↓
Project structure
   ↓
Documentation discovery
   ↓
Runtime/environment discovery
   ↓
Claims
   ↓
Regions
   ↓
Edges
   ↓
FrameПосле нескольких шагов агент уже находится **не в пустой коробке**, а в собственной карте окружающего мира.
```


# Важно

Не делать Bootstrap Knowledge отдельной «базой знаний». Это должен быть тот же самый substrate, который постепенно пополняется обычным наблюдением агента. Иначе мы снова незаметно вернёмся к старой архитектуре `RAG + memory + agent`. Здесь гораздо интереснее модель: **агент приходит в новый мир с пустой памятью, исследует его, а его карта мира возникает как побочный продукт реального взаимодействия с миром.**
