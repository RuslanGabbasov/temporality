02 / ЧЕТЫРЕ СЛОЯ

Один контур
из четырёх слоёв.

Исполнение и наблюдение дают агентам рабочую среду. Контроль делает её управляемой, а обучение — накапливающей: проверенный опыт возвращается в следующие задачи знаниями и навыками.

01
▶

Исполнение

Долгоживущие задачи на Temporal: делегирование подагентам, планы-графы, паузы для вопроса человеку. Перезапуск сервиса или деплой задачу не прерывают.

TEMPORAL WORKFLOWS
02
◉

Наблюдение

Событийный журнал каждого шага: вызовы модели и инструментов, живая консоль команд, реконструкция причин инцидента по трассе — от события до исходного вопроса.

03

03 / ЁМКОСТЬ

Сколько агентов
тянет один сервер.

Ориентир для планирования: одна 6-ядерная виртуальная машина держит сотню одновременных агентов в тяжёлом сценарии — четыре хода модели, команды в песочнице, ожидание человека, ~9,4 минуты на прогон. Запуски — независимые workflow: при росте нагрузки масштабируется добавлением ресурсов, а не переписыванием.

04 / БЫСТРЫЙ СТАРТ

Поднять локально.
Подключить модель.
Запустить агента.

Короткий путь до первого запуска: две команды — модель, первый агент и песочница настраиваются в мастере онбординга.

1

Заберите compose-файл

Нужен только Docker Compose — образы уже собраны и опубликованы для amd64 и arm64.

mkdir temporality && cd temporality
curl -o docker-compose.yml https://raw.githubusercontent.com/RuslanGabbasov/temporality/main/docker-compose.yml
2

Запустите стек

Compose поднимет PostgreSQL, журнал событий, интерфейс, Temporal, ядро агентов и веб-инструменты. По умолчанию берётся последний опубликованный релиз; конкретную версию можно закрепить переменной TEMPORALITY_VERSION. Мастер онбординга проведёт первый запуск: проект → провайдер → агент → песочница.

docker compose up -d

Последний релиз v2026.2.113 · все релизы ↗ · обновиться: docker compose pull && docker compose up -d

Для продакшена задайте KERNEL_SECRET_MASTER_KEY в .env до первого запуска — ключ шифрования секретов. Остальное настраивается в мастере.

3

Откройте интерфейс

Веб-интерфейс — на порту 3000, интерфейс Temporal — на 8233. Для локальной разработки авторизация выключена, если токены не заданы.

Веб-интерфейсhttp://localhost:3000
Temporal UIhttp://localhost:8233

ПЕРВЫЙ СЕАНС

С чего начать после запуска

  1. Настройте провайдера модели.
  2. Создайте или выберите агента.
  3. Запустите простую задачу с проверяемым результатом.
  4. Посмотрите события запуска и предложенные знания.
  5. Проверьте происхождение и повторное использование опыта.

06 / СРАВНЕНИЕ

Не вместо вашего фреймворка.
Вокруг него — теперь по-настоящему.

Память (Mem0, Zep) запоминает. Трассировка (LangSmith, LangFuse) показывает. Фреймворки (LangGraph, CrewAI) оркестрируют. Temporality закрывает недостающий слой: надёжное исполнение и опыт с происхождением и жизненным циклом — связанные с людьми, правами и качеством. Модель — любой OpenAI-совместимый провайдер, инструменты — ваши MCP-серверы, каналы — ваши мессенджеры, данные — ваш PostgreSQL; журнал и подсказки доступны по HTTP любому агенту — включая агентов чужого фреймворка.

⟳

Надёжность с первого дня

Задачи живут в Temporal: перезапуск сервиса, деплой или уснувший ноутбук не убивают работу — она продолжается с места остановки.

◉

Опыт, а не свалка

У каждого знания — автор, источник и статус. Устаревшее не подсматривается, противоречия не теряются, а решаются.

⚖

Качество как процесс

Изменения агентов и навыков проходят проверку на эталонных кейсах и судью-модель с калибровкой. Человек утверждает — система не меняет себя сама.

⛨

Безопасность по умолчанию

Команды — в изолированной песочнице без привилегий; секреты агенту не видны; значимые действия — только после подтверждения; сверху — права доступа и политики оргструктуры.

☕

Люди в контуре, а не в узком месте

Подтверждения и вопросы приходят в ваш мессенджер и решаются оттуда. Метрики HAB/HWT показывают, где поток упирается в людей — внимание это или простой.

⌂

Своя инфраструктура

Весь стек — одним docker compose: PostgreSQL, Temporal, журнал и интерфейс у вас. MCP-серверы и OpenAI-совместимые модели подключаются напрямую.

07 / ДЛЯ КОМАНД

Для компаний,
внедряющих агентные системы.

Средние и крупные команды с повышенными требованиями к безопасности, отказоустойчивости и измеримости: агенты работают в производственных процессах — и их работа проверяема, управляема и не теряется.

01
⛨

Безопасность

Self-hosted: ваши ключи, ваши данные, ваш PostgreSQL. Egress-прокси с allowlist на агента, секреты вне досягаемости, подтверждения значимых действий, аудит каждого обхода.

ВАША ИНФРАСТРУКТУРА
02
▶

Отказоустойчивость

Задачи — durable workflows: деплой, рестарт или сон ноутбука задачу не прерывают. Ответы журналируются, ответы людей приходят из мессенджеров, и ничто не исчезает между шагами.

TEMPORAL DURABILITY
03
◆

Измеримость

Эволюция агентов через оценочный гейт: предложение применяется только с зелёным прогоном на кейсах — или с обоснованным оверрайдом в аудите. Регрессии по точности, ходам и токенам видны по версиям; откат — в один клик.

ВЕРСИИ И ОТКАТЫ
04
💬

Команда на связи
