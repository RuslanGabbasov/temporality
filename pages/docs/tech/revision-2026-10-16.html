Ревизия планов: что не реализовано (2026-10-16)

Полная ревизия «план → код» по шести направлениям (секреты, артефакты, знания/навыки, каналы/intake/триггеры/саги, платформа агентов, хвосты ROADMAP). Доказательства — файл:строка по дереву e02b638.

#В работе (волна фиксов, октябрь 2026)

  1. ✅ Согласование артефактов (сделано): решение матчится с записями согласующих через профиль принципала (MatchArtifactReviewers) — групповые записи (org:/role:/project_owner) решает любой активный участник, решение хранится под записью с decided_by; правка approved теперь 409 (SaveArtifactEdit), а не молча снимает статус; кнопка правки в UI заблокирована.
  2. ✅ Event-триггеры (сделано): слушатель журнала (cmd/agent-kernel/eventtriggers.go) — хвост журнала с курсором journal:events, срабатывание только на пост-активационных событиях (без переигрывания истории), идемпотентность по (trigger, event), анти-цикл на события триггерных ранов, без event-триггеров журнал не читается. Конструктор: event_type + фильтры actor_id/actor_type/project/data.<поле> (валидация на сохранении, неизвестные ключи — 422) + промпт; UI-форма с подсказками типов и чипами фильтров. Контракт: docs/triggers-and-escalations.md §1.
  3. ✅ kernel/probe (решено — удалён): пробы нерабочие по предпосылкам — FileProbe ждал > отдельным argv-токена (реальные run_command несут редиректы внутри sh -c-строки, см. трейсы), MCPProbe читал назад собственный журнал ядра (циркулярно). Боль подтверждения побочных эффектов закрыта классификацией эффектов при сбоях (toolFailureData) и операциями с эффектами; заметка в ROADMAP P2.
  4. ✅ Slack-треды + настройки каналов (сделано): thread_ts на исходящих, thread_ref на вопросах (human_request, миграция 000065), точный матчинг тредовых ответов с бэкфиллом; настройки каналов — аккордеон (настроенные сверху, раскрыты). Контракт: docs/channels.md §9.1.
  5. ✅ Approved-хвосты (сделано): skill_inspect отдаёт status/version и помечает не-утверждённые артефакты предупреждением; artifact_search принимает status=/kind= и отдаёт origin_type; редактор навыков предлагает только approved.
  6. ✅ Уведомления согласующим (сделано): submit рассылает текстовое уведомление со ссылкой каждому раскрытому согласующему по каналу с той же политикой выбора, что ask_human (cmd/agent-kernel/artifactnotify.go), вне цикла запроса, best-effort.

#2. Секреты (secrets-management.md)

Фаза 1 — закрыта в основном; хвосты:

  • тул secret_request (HITL-выдача) — нет;
  • события secret.accessed / secret.revoked, lease_id/ttl — нет (есть secret.issued/secret.denied);
  • git credential helper — git-операции только через env;
  • tmpfs-секрет-файлы для legacy-тулов — нет;
  • secret:// в конфигах агентов (гранты именами) и триггерах — нет;
  • UI: фильтры по оргединице/провайдеру, пикер secret:// в MCP-форме — нет.

Фаза 2 — ❌ целиком: SecretProvider-контракт, адаптеры Infisical/Vault, динамические секреты, TTL-lease, ротация по расписанию, revoke, gейтинг политиками (провайдеры жёстко builtin|env, migrations/000050).

Фаза 3 — ❌ целиком: GitHub Apps-брокер, OIDC/STS-федерация, SIEM-экспорт аудита.

Нюанс: resolve-эндпоинт (main.go:4771-4812) проверяет service-principal, но не орг-видимость — разграничение на стороне ядра (sandboxSecretEnv).

#3. Артефакты

Lifecycle Фаза 2 — 0/3: кнопки approve/reject в каналах (база — human_requests с orphan-RunID — тоже нет, channelinbound.go:291-320 сигналит только в workflow рана); напоминания ARTIFACT_REVIEW_TIMEOUT — только в доке; эскалация — не решено, кому (артефакты не привязаны к проектам; кандидат — head оргединицы).

Lifecycle Фаза 3 — 0/4: снапшоты тел (правка затирает, workspace/artifacts.go:304-307), пиннг версии в манифесте (skills/manifest.go:19-22 — только ID), трассировка сага→раны→фича (в ProjectOverview.tsx артефактов нет), конвертация work→reference.

Registry Фаза 3 — 0/3: адаптеры S3/СЭД (провайдеры жёстко builtin|url, main.go:7351), версионирование, полнотекстовый поиск (только метаданные).

Открытые вопросы §14 lifecycle: ко-редактирование черновиков, обязательный ревью человеческих reference, агентское пред-ревью, пиннг vs always-latest, квоты размера агентских черновиков.

Прочее: статус superseded и события artifact.superseded/artifact.updated не эмитятся; cancelled у review — мёртвое значение; kind-чипа-фильтра в UI нет.

#4. Каналы / intake / триггеры / саги

  • Interactivity (кнопки Telegram/Slack + текстовый фолбэк) — ❌; основа OutboundText.Options []string, рендер текстом.
  • MS Teams — ❌ ни драйвера, ни заготовки.
  • Mattermost не парсит file-only посты; у Slack нет FilesIn; телеграм не режет 4096; capabilities-контракт беднее докового (нет Threads/Interactive/MaxTextLen).
  • Intake: фазы 1–4 закрыты (глобальный kill-switch KERNEL_INTAKE_ENABLED + пер-проектный intake_enabled, 422). Будущее §14 (кворумы, создание проекта из канала) — не начато.
  • Триггеры: нет non-blocking notify; нет счётчиков запусков/«требовался человек» в UI; options без id/label; эскалация только project_owner; имена событий дока human.delivered/response_received/run.resumed не совпадают с кодом.
  • Саги: ядро закрыто (инструменты, автопривязка, бюджеты, UI). Открыты (осознанно): замыкание, авто-предложение в промптах, stale-индикатор, кросс-проектность.

#5. Навыки и знания

  • Contextual memory retrieval per skill/capability — ❌ (навыки в priming — только novelty-штраф; skill_memory — листинг).
  • Evolution analytics для навыков — ❌ (у агентов есть agentEvolution.ts; у навыков только счётчики Skills.tsx:559-565).
  • Eval-gate качества не распространяется на навыки: гейт только на agent-proposals (main.go:2293); skill apply без гейта; judge-поля skill-оценок не заполняются (kernel/agent/skilleval.go:42-45).
  • living-skills: deprecated-состояния, dry-run skill.apply (§24), memory.confirm (§25), метрики качества навыка (§30), композиция навыков — нет; aging-sweep (aging.v1, 14 дней → challenged) — частично закрывает устаревание.
  • knowledge-evolution: сценарий C частично (challenge есть, автоинвалидации нет; knowledge.disproved/corrected/linked валидируются, но продюсеров нет); подтверждение = 1 ре-выведение, порогов нет.
  • knowledge-extraction: ручной confirm кандидатов в UI нет (только challenge/invalidate); extraction не запускается для team-root ранов и run.failed.
  • knowledge-model: valid_from/valid_to нет (битемпоральность — query-фильтры); Evidence урезан до Ref+Type; kind не валидируется; переходы asserted/expired/forgotten нет.
